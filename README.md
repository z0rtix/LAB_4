## О проекте

Реализация семейства абстрактных типов данных для работы с потенциально бесконечными (ленивыми) последовательностями.  
Основой служит `LazySequence<T>` – контейнер, который может быть бесконечным, но хранит в памяти только уже вычисленные элементы. Остальные элементы задаются порождающим правилом (генератором) и материализуются по мере необходимости.  

Поверх ленивых последовательностей построены потоки (`Stream<T>`) и конечный автомат Мили (`StateMachine<TInput, TOutput>`). Демонстрация совместной работы всех трёх АТД: бесконечная последовательность событий (например, числа Фибоначчи) подаётся через поток в автомат, который обрабатывает каждый символ и выдаёт выходной поток.

Все алгоритмы покрыты модульными тестами, оснащены консольным меню с русифицированным интерфейсом и проверкой на утечки памяти (Valgrind/AddressSanitizer).

## Ключевые архитектурные решения

### Ординарная длина последовательности (`Cardinal`)
Для описания длины потенциально бесконечной последовательности введён класс `Cardinal`, реализующий ординарную арифметику: конечные числа, бесконечность ω, а также ω·k + n для k бесконечных блоков, объединённых через `concat`.  
Используется во всех методах `LazySequence`, где требуется знать длину, проверять принадлежность индекса или вычислять смещения внутри цепочки сегментов.

### Сегменты и композиция генераторов
Внутри `LazySequence<T>` данные хранятся как `MutableArraySequence<Segment*>` – массив указателей на **сегменты**. Сегмент может быть:
- **Конечным (`FiniteData`)** – содержит готовый массив элементов (например, результат `append`).
- **Генераторным (`Generator`)** – содержит функцию-генератор и уже материализованную часть. При запросе элемента, выходящего за границы материализованного, генератор достраивает новые значения и сохраняет их (мемоизация).

Такая архитектура позволяет:
- Объединять несколько бесконечных последовательностей (`concat` двух генераторов даёт ω·2).
- Добавлять конечные элементы после бесконечности (`append` к бесконечной создаёт новый конечный сегмент, доступный по индексам ω, ω+1, …).
- Строить ленивые отображения (`map`) – создаётся новый генератор, который при запросе дёргает исходную последовательность и применяет функцию.

### Ленивость и мемоизация
- **Ленивость:** элементы не вычисляются заранее. Генератор запускается только при вызове `get(index)`.
- **Мемоизация:** каждый вычисленный элемент сохраняется в `data` соответствующего сегмента. Повторные обращения к тому же индексу происходят за O(1).
- **Неизменяемость:** операции модификации (`append`, `set` и т.п.) возвращают новый объект `LazySequence`, оставляя исходный без изменений.

### Использование `MutableArraySequence<Segment*>` вместо `std::vector`
Хранение сегментов по указателям решает проблему глубокого копирования: `MutableArraySequence::get(i)` для типа `Segment*` возвращает указатель (быстро), а не копию всего сегмента (что привело бы к копированию всех материализованных данных).  
При операциях копирования (`copy`, `concat`) сегменты клонируются через `new Segment(*ptr)`.

### Отсутствие ввода-вывода в заголовках
Все заголовки не содержат `#include <iostream>`, `<fstream>` и т.п. Вывод и работа с файлами (если есть) вынесены в `.cpp`-файлы. Шаблонные классы (`LazySequence`, `Stream`, `StateMachine`) реализованы в заголовках, но без использования потоков ввода-вывода.

## Функциональность `LazySequence<T>`

### Конструкторы
- По умолчанию – пустая конечная последовательность.
- Из массива, из существующей `Sequence<T>`.
- Из генератора: `LazySequence(gen, initial, length)`, где `gen` – правило `T(const Sequence<T>&)`, `initial` – начальные элементы, `length` – ожидаемая длина (конечная или `Infinite`).

### Методы доступа
- `getFirst()`, `getLast()`, `get(int)`, `get(Cardinal)` – доступ по конечным и ординарным индексам.
- `getLength()`, `isEmpty()`, `cardinalLength()`, `getMaterializedCount()`.
- `getSubsequence(start, end)` – для любых индексов (включая бесконечные) материализует нужные элементы и возвращает конечную последовательность.

### Операции изменения
- `append(item)`, `prepend(item)`, `insertAt(item, index)`, `set(item, index)`.
- `removeFirst()`, `removeLast()`, `removeAt(index)`, `clear()`.
- Для бесконечных последовательностей `prepend`, `insertAt`, `remove*` запрещены (исключение).
- `append` к бесконечной добавляет новый конечный сегмент, индексы становятся ω, ω+1, …
- `set` на бесконечной изменяет уже материализованный элемент, влияя на дальнейшую генерацию (патчинг).

### Композиция
- `map(function)` – ленивое преобразование. Создаёт новый генератор, который при запросе применяет функцию к элементу исходной последовательности.
- `where(predicate)` – фильтрация (для конечных – полная, для бесконечных – ограничена первыми 1000 элементами для демонстрации).
- `concat(Sequence*)`, `concat(LazySequence*)` – объединение последовательностей с правильной ординарной длиной.

### Ординарные индексы
После добавления конечных элементов к бесконечной последовательности они получают индексы ω, ω+1, ω+2, …  
Пример:
```cpp
LazySequence<int> fib = ...; // бесконечная Фибоначчи
LazySequence<int>* ext = fib.append(100)->append(200);
cout << ext->get(Cardinal::InfinitePlus(0)); // 100
cout << ext->get(Cardinal::InfinitePlus(1)); // 200
```

## Потоки (`Stream<T>`)

- `ReadOnlyStream<T>` – последовательное чтение из `Sequence<T>*`. Поддерживает `Seek`, определяет конец потока через исключение `std::out_of_range`.
- `WriteOnlyStream<T>` – последовательная запись в `Sequence<T>*`.
- Используются автоматом для получения входных данных и выдачи результата.

---

## Конечный автомат (`StateMachine<TInput, TOutput>`)

- Классический автомат Мили: выход зависит от текущего состояния и входного символа.
- Методы: `AddTransition(from, input, to, output)`, `SetInitialState(state)`, `ProcessSymbol(input)`, `ProcessStream(inputStream, outputStream)`, `Reset()`, `GetCurrentState()`.
- Демонстрация: бесконечная последовательность подаётся через `ReadOnlyStream`, обрабатывается автоматом, результат записывается в `WriteOnlyStream`.

## Консольное меню

Полностью на русском языке с пояснениями. Пункты:
1. **Демонстрация Фибоначчи** – показ первых чисел, добавление элементов, ординарные индексы, `map`.
2. **Демонстрация автомата** – обработка входного потока автоматом.
3. **Создание новой последовательности** – выбор из готовых генераторов или ввод конечной.
4. **Песочница операций** – разовая работа с последовательностью (создание, модификация, просмотр).
5. **Ручные операции** – постоянная последовательность сохраняется между вызовами меню.
6. **Запуск всех тестов** – прогон модульных тестов.
7. **Стресс-тест Фибоначчи** – 1 миллион обращений с замером времени.
8. **Таблица производительности** – сравнительный вывод времени выполнения тестов для `int`/`double`.
0. **Выход**.

Все операции сопровождаются защитой от некорректного ввода (функции `readInt`, `readLongLong` со сбросом потока).
